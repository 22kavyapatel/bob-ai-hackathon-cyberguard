# Setup Guide

> **This file is read by the automated evaluation pipeline. Be precise and complete.**

## Prerequisites

Before you begin, ensure you have the following installed:

- [ ] Python 3.11 or higher (`python --version`)
- [ ] Node.js 18 or higher (`node --version`)
- [ ] npm 9+ (`npm --version`)
- [ ] Git

**Optional (for AI-powered BLUF summaries):**
- [ ] An IBM Cloud account with IBM watsonx.ai access
- [ ] A watsonx.ai API key and Project ID

> ⚠️ **The application runs fully without an IBM Cloud account.** Without an API key, BLUF summaries are generated by the built-in rule-based fallback. All other features (correlation, risk scoring, MITRE mapping, filtering) work offline.

## Environment Variables

Copy `.env.example` to `.env` inside the `src/` directory and fill in the values:

```bash
cd src
cp .env.example .env
```

| Variable | Description | Required |
|---|---|---|
| `WATSONX_API_KEY` | Your IBM watsonx.ai API key | No (uses fallback) |
| `WATSONX_PROJECT_ID` | Your watsonx.ai project ID | No (uses fallback) |
| `WATSONX_URL` | watsonx.ai regional endpoint | No (defaults to `https://us-south.ml.cloud.ibm.com`) |
| `BACKEND_PORT` | Port for the FastAPI server | No (defaults to `8000`) |
| `FRONTEND_ORIGIN` | Allowed CORS origin | No (defaults to `http://localhost:5173`) |

## Installation

### 1. Clone the Repository

```bash
git clone https://github.com/your-org/bob-ai-hackathon-cyberguard.git
cd bob-ai-hackathon-cyberguard
```

### 2. Backend Setup (Python)

```bash
cd src/backend

# Create and activate a virtual environment (recommended)
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### 3. Frontend Setup (Node.js)

```bash
cd src/frontend
npm install
```

## Running the Application

You need **two terminals** — one for the backend and one for the frontend.

### Terminal 1 — Backend

```bash
cd src/backend
# Activate venv if not already active
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS / Linux

uvicorn main:app --reload --port 8000
```

The API will be available at **http://localhost:8000**

Verify it's running: http://localhost:8000/health → should return `{"status":"ok"}`

### Terminal 2 — Frontend

```bash
cd src/frontend
npm run dev
```

The dashboard will be available at **http://localhost:5173**

## Quick Demo

Once both servers are running:

1. Open **http://localhost:5173** in your browser.
2. You will see the ThreatSense AI dashboard with 50 simulated alerts.
3. Use the **severity / source / status** filters in the top bar to filter alerts.
4. Click any alert row to open the **detail panel** on the right.
5. The panel shows: risk score, classification, correlated alerts, MITRE ATT&CK techniques, BLUF summary, and recommended actions.
6. Click **Open → In Review → Closed** buttons to update the alert status.

## Troubleshooting

| Issue | Solution |
|---|---|
| `ModuleNotFoundError` on backend start | Run `pip install -r requirements.txt` inside your activated venv |
| `CORS error` in browser console | Make sure both servers are running — backend on port 8000, frontend on 5173 |
| `npm: command not found` | Install Node.js 18+ from https://nodejs.org |
| `python: command not found` | Use `python3` instead; ensure Python 3.11+ is in your PATH |
| watsonx.ai `401 Unauthorized` | Check `WATSONX_API_KEY` in your `src/.env` file; the app will fall back to rule-based summaries without it |
| Port 8000 already in use | Change `BACKEND_PORT` in `.env` and update `src/frontend/src/config.ts` accordingly |
| Port 5173 already in use | Vite will automatically try the next available port; update the CORS origin in `.env` to match |
